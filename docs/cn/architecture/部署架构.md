# 部署架构

**一句话概括**：浏览器经边缘 Nginx 走 HTTPS 进入集群，Traefik 按 Ingress 规则把 `/` 交给前端静态站点、把 `/api` 交给 api-gateway；其余服务（user-service、PostgreSQL、Redis）只在集群内可达。

## 术语速查（K8s 组件在本项目中的对应）

| 概念 | 作用 | 本项目实例 |
|------|------|-----------|
| Namespace | 资源隔离边界 | `museflow`（业务）、`traefik`（Ingress Controller） |
| Deployment | 无状态工作负载，维持副本数、滚动更新 | `web`、`api-gateway`、`user-service`、`user-service-worker` |
| StatefulSet | 有状态工作负载，稳定的 Pod 名与独立 PVC | `postgres`、`redis`、`ollama` |
| Pod | 最小运行单元，由 Deployment/StatefulSet 管理 | `web-xxxx`、`api-gateway-xxxx` |
| Service | 给一组 Pod 提供集群内固定虚拟 IP 与 DNS 名，并做负载均衡 | `web:80`、`api-gateway:5001`、`user-service:5002` |
| Service：ClusterIP | 仅集群内可达（默认类型） | `web`、`api-gateway`、`user-service` |
| Service：NodePort | 在每个节点上开放 `30000-32767` 中的一个端口 | Traefik：`31380` / `31443` |
| Service：LoadBalancer | 由云厂商或 `klipper-lb` 分配外部 IP | 本地调试用的 `postgres`、`redis` |
| Ingress | 声明「域名 + 路径 → Service」的路由规则（**只是规则，本身不转发流量**） | `museflow`（`deploy/k8s/edge/ingress`） |
| IngressClass | 规则交给哪个控制器执行 | `traefik`（K3s 自带且为默认） |
| Ingress Controller | 真正实现路由的反向代理 | `traefik` 命名空间中的 Traefik |
| ConfigMap | 非敏感配置，注入为环境变量或文件 | `api-gateway-config`、`user-service-config`、`web-config`（站点 nginx.conf） |
| Secret | 敏感配置 | `*-secret`，值来自未提交的 `overlays/secrets.yaml` |
| PVC | 持久化存储声明 | `data-postgres-0`、`data-redis-0`、`data-ollama-0` |
| Helm Release | 一次 Chart 部署的版本记录，可升级/回滚 | `postgres`、`redis`、`api-gateway`、`web`、`ingress`… |

**最容易混淆的三组**

- **Service ≠ Ingress**：Service 是四层的集群内固定入口（IP + 端口 + 负载均衡）；Ingress 是七层的路由规则（按域名与路径分流），必须由 Ingress Controller 实现。Ingress 的 `backend` 指向的正是 Service。
- **NodePort ≠ 对外可用**：NodePort 只是「在节点上开一个端口」，没有域名路由也没有 TLS。本项目只把 **Traefik 的 NodePort** 交给边缘 Nginx，业务服务一律 ClusterIP。
- **IngressClass ≠ Ingress Controller 实例**：`ingressClassName: traefik` 只表示「这条规则交给 traefik 这个控制器」；真正干活的是 `traefik` 命名空间里的 Pod，规则没生效时先看它。

## 分层拓扑

```
Browser
  │ HTTPS（证书在边缘 Nginx）
  ▼
边缘 Nginx（集群外，唯一终止 TLS 的位置）
  │ HTTP，保留 Host 头
  ▼
Traefik NodePort 192.168.142.121:31380（集群内唯一路由入口）
  │ Ingress「museflow」按 Host + Path 路由
  ├── /      ──▶ Service web:80            （SPA 静态产物）
  └── /api   ──▶ Service api-gateway:5001  （/api/v1/** 原样透传）
                     │ gRPC
                     ▼
                Service user-service:5002
                     │
              PostgreSQL / Redis（仅集群内可达）
```

职责边界：

| 组件 | 职责 | 明确不做什么 |
|------|------|-------------|
| 边缘 Nginx | 终止 HTTPS、加载证书、整体转发到 Traefik NodePort | 不做路径级路由、不托管前端资源 |
| Traefik | 集群内唯一入口，按 Host + Path 转发到 Service | 默认不终止证书（由边缘负责） |
| `web`（frontend） | 只托管 SPA 静态文件、SPA 路由回退 | 不配置任何 `proxy_pass` |
| `api-gateway` | `/api/v1/**` 全部接口、CORS、Cookie、JWT 校验 | 不参与静态资源服务 |

## 请求链路（逐跳）

以 `https://<域名>/api/v1/auth/login` 为例：

1. **浏览器 → 边缘 Nginx:443**：DNS 解析到边缘 Nginx 所在服务器，TLS 在此终止。
2. **边缘 Nginx → `192.168.142.121:31380`**：整体反代（`proxy_pass`），保留 `Host` 头——Traefik 靠它匹配 Ingress 规则。
3. **Traefik → Ingress 规则**：按 `Host: <域名>` + `Path: /api` 选中 `api-gateway` 这条 route。
4. **Traefik → Service `api-gateway:5001`**：Service 是 ClusterIP，负责把流量负载均衡到某个 api-gateway Pod。
5. **api-gateway → `user-service:5002`**：走 gRPC，地址直接用 Service 名，由集群内 DNS 解析。
6. **user-service → `postgres:15432` / `redis:6379`**：同样通过 Service 名访问，服务地址来自 `overlays/secrets.yaml` 的 `DB_*` / `REDIS_ADDR`。

静态资源的链路更短：`/` 命中 `web:80`，由容器内 Nginx 直接返回前端构建产物。

## 路由规则

| 路径 | 后端 | 说明 |
|------|------|------|
| `/` | `web:80` | 静态资源 + SPA 路由回退 |
| `/api` | `api-gateway:5001` | `/api/v1/**` 原样透传，网关不感知前缀变化 |
| `/health` | `api-gateway:5001` | 网关健康检查，不需要时从 `paths` 中移除 |

Traefik 按最长前缀优先匹配，`/api` 不会被 `/` 覆盖。规则由 Helm Chart `deploy/k8s/edge/ingress` 声明，路径列表在 `edge/ingress/values.yaml` 的 `ingress.paths`。

## 各组件的暴露范围

| 组件 | 集群内地址 | 集群外 |
|------|-----------|--------|
| `web` | `http://web:80` | 经边缘 Nginx + Ingress（`/`） |
| `api-gateway` | `http://api-gateway:5001` | 经边缘 Nginx + Ingress（`/api`、`/health`） |
| `user-service` | `user-service:5002`（gRPC） | 不暴露 |
| `postgres` | `postgres:15432` | 默认不暴露；`base/overlays/values.yaml` 的 `postgres.service` 可临时改为 NodePort / LoadBalancer 供本地调试 |
| `redis` | `redis:6379` | 同上 |
| Traefik | — | `192.168.142.121:31380`（HTTP）/ `31443`（HTTPS） |
| Ollama / SearXNG | `ollama:*`、`searxng:*` | 不暴露 |

> 生产环境应保持 `user-service`、PostgreSQL、Redis 只在集群内可达；只有在本地调试时才临时放通数据库端口。

## 域名与证书

域名是环境信息，唯一来源为 `deploy/k8s/applications/overlays/secrets.yaml`（未提交）；
本文档中的示例域名统一使用 `museflow.com`：

```yaml
domain:
  host: museflow.com
  scheme: https
```

其余域名相关配置由 Chart 模板派生，禁止在 `values.yaml` 重复填写：

| 派生目标 | 派生规则 | 实现位置 |
|---------|---------|---------|
| Ingress `rules[].host` | `domain.host` | `deploy/k8s/edge/ingress/templates/_helpers.tpl` |
| `GATEWAY_ALLOW_ORIGINS` | `<domain.scheme>://<domain.host>`，附加 `apiGateway.extraAllowOrigins` | `deploy/k8s/applications/services/api-gateway/templates/_helpers.tpl` |
| `USER_TURNSTILE_ALLOWED_HOSTNAMES` | `domain.host`，附加 `userService.extraTurnstileHostnames` | `deploy/k8s/applications/services/user-service/templates/_helpers.tpl` |

`domain.host` 缺失时 `helm template` / `helm lint` 直接报错，不会静默渲染成空域名或历史域名。

HTTPS 与证书在集群外终止，配置位于 `deploy/k8s/edge/nginx/museflow.com.conf`（示例域名 `museflow.com`，部署时替换为 `domain.host`）；证书签发与服务器落盘步骤见 `deploy/k8s/README.md` 的「访问入口与域名」。

更换域名的操作：

1. 修改 `deploy/k8s/applications/overlays/secrets.yaml` 的 `domain.host`。
2. 边缘 Nginx 同步更新 `server_name` 与证书目录，继续反代到 `192.168.142.121:31380`。
3. 重新部署 `app` 范围（或只重建 `ingress`、`api-gateway`、`user-service` 三个 release）。
4. 校验：`kubectl get ingress -n museflow`，再从边缘入口访问 `/` 与 `/api/v1/**`。

## 部署操作

Chart 分两组：`base/`（PostgreSQL、Redis、Ollama、SearXNG）与 `applications/`（业务应用 + `edge/ingress`）。
真实密钥与域名放在两个未提交的 `secrets.yaml` 中，部署脚本会先校验它们是否存在。

```bat
:: Windows：按范围部署，默认 all
deploy\k8s\scripts\deploy.bat base --kubeconfig=E:\kubeconfig\xxx.yaml
deploy\k8s\scripts\deploy.bat app  --kubeconfig=E:\kubeconfig\xxx.yaml
deploy\k8s\scripts\deploy.bat all  --kubeconfig=E:\kubeconfig\xxx.yaml
```

```bash
# Linux/macOS
./deploy/k8s/scripts/deploy.sh app --kubeconfig=/path/to/kubeconfig
```

边缘 Nginx 不属于 Helm 管理，需要手工放到服务器上：

| 仓库路径 | 服务器路径 |
|---------|-----------|
| `deploy/k8s/edge/nginx/museflow.com.conf` | `/etc/nginx/conf.d/museflow.com.conf` |
| — | `/etc/nginx/certs/<域名>/fullchain.pem`、`privkey.pem` |

完整命令（手动 Helm、校验、升级回滚、卸载与数据保留）见 `deploy/k8s/README.md`。

节点拉不到镜像时，用 `deploy/k8s/scripts/push-image.sh`（或 `.bat` / `.ps1`）把本机构建的镜像
`docker save` 后上传到服务器 `/docker/images`，再由 `ctr -n k8s.io images import` 导入 K3s 的
containerd；用法见 `deploy/k8s/README.md` 的「离线镜像导入」。

## 排查

| 现象 | 先看什么 |
|------|---------|
| 域名访问 502/503 | `kubectl get pods -n museflow`；再确认 Ingress 的后端 Service 有 Endpoints：`kubectl get endpoints -n museflow` |
| 域名访问 404（页面为网关 JSON） | Ingress 命中但路径不对：路由规则见 `ingress.paths`，网关只认 `/api/v1/**` |
| 域名访问 404（Traefik 默认 404 页） | Ingress 未命中：`kubectl get ingress -n museflow` 看 host 是否等于浏览器里的域名 |
| 浏览器没带上 Cookie | 边缘是否真的是 HTTPS；`GATEWAY_COOKIE_SECURE=true` 时 HTTP 不会回传 Cookie |
| 日志出现 `invalid-input-secret` | 人机验证填的是前端 Site Key 或仍是占位符：改 `applications/overlays/secrets.yaml` 的 `USER_TURNSTILE_SECRET`；留空表示跳过验证（仅适合本地） |
| SSE 状态流不实时 | 边缘 Nginx 的 `proxy_buffering off` 与网关的 `X-Accel-Buffering: no` 是否都在 |

常用命令：

```bash
kubectl get pods,svc,deploy,statefulset,pvc,ingress -n museflow --kubeconfig=<kubeconfig>
kubectl get events -n museflow --sort-by=.lastTimestamp --kubeconfig=<kubeconfig>
kubectl logs -n museflow deployment/api-gateway --tail=100 --kubeconfig=<kubeconfig>
helm list -n museflow --kubeconfig=<kubeconfig>
helm history api-gateway -n museflow --kubeconfig=<kubeconfig>
```

## 目录结构

```
deploy/k8s/
├── applications/          # 业务应用 Chart：services/、web/、overlays/（真实密钥与域名）
├── base/                  # 基础服务 Chart：postgres、redis、ollama、searxng
├── edge/                  # 对外入口层
│   ├── ingress/           # 集群内路由：Traefik Ingress（Helm Chart）
│   └── nginx/             # 集群外边缘 Nginx：HTTPS 终止 + 反代 Traefik
├── scripts/               # deploy.sh / deploy.bat / deploy.ps1
└── README.md              # 部署命令手册
```
