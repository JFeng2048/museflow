# 架构设计文档

本目录存放**架构级**设计文档，回答「系统由哪些部分组成、各部分部署在哪里、彼此如何通信」。

与 `docs/cn/develop/` 的分工：

| 目录 | 回答的问题 | 例子 |
|------|-----------|------|
| `docs/cn/architecture/`（本目录） | 系统由什么组成、怎么部署、怎么通信 | 部署架构、服务架构设计 |
| `docs/cn/develop/` | 某个功能具体怎么实现 | 双令牌认证、2FA、Turnstile、权限校验 |
| `docs/cn/api/` | 对外接口契约 | api-gateway、config-service、user-service、crawl4ai-service |

## 文档索引

| 文档 | 内容 |
|------|------|
| [部署架构](部署架构.md) | K8s 组件速查（Namespace / Deployment / Service / Ingress / …）、分层拓扑、请求链路逐跳说明、路由规则、部署与排障 |
| [服务架构设计](服务架构设计.md) | 服务与模块划分、分层与依赖约束、数据持久化、关键技术设计、关联的实现细节文档 |

## 新增文档约定

为了让文档可以持续增补而不失控：

- **命名**：中文文件名，直接写主题（`部署架构.md`、`消息队列设计.md`、`可观测性方案.md`），不加编号前缀，便于按名字插入与删除。
- **开头**：每篇文档第一段写「一句话概括」，先给结论，再展开细节。
- **写实**：涉及路径、命令、配置项一律使用仓库中的真实值（相对仓库根目录），不要写占位符。
- **互链**：本目录内用相对链接互引；引用实现细节用 `../develop/xxx.md`，引用接口用 `../api/xxx.md`。
- **登记**：新增文档后，在本文档的「文档索引」表里补一行。
- **英文镜像**：对应英文文档放在 `docs/en/architecture/`，文件名用英文短横线风格（`deployment.md`）。
