# 测试文档

## 测试策略

- 后端使用标准 `testing` 包，测试文件与源码同目录（`*_test.go`）。
- 通过内存 fake（`repository.UserRepository` / `TokenStore` 等）隔离外部依赖，
  不依赖真实 PostgreSQL / Redis。
- 前端使用 Vitest，`*.spec.ts` 与源码同目录。

## user-service 测试覆盖

`internal/service/auth` 为主要覆盖包，包含：

| 测试文件 | 覆盖点 |
|----------|--------|
| `auth_service_test.go` | 注册、登录（含 2FA 两步）、登出、改密、锁定、会话列表 |
| `reset_password_test.go` | 邮件验证码发送/校验/重置、重发冷却 |
| `oauth_test.go` | OAuth 绑定/登录/解绑 |
| `mfa.go` 相关用例 | Setup/Verify/Disable/Regenerate/GetStatus/VerifyMFALogin |

`internal/service/mfa` 包覆盖 TOTP 密钥生成、验证码校验（含时钟偏移）、恢复码生成与单次校验。

## 运行测试

```bash
# 全量
cd services/user-service && go test ./...

# 单包
go test ./internal/service/auth/ -v

# 单用例
go test ./internal/service/auth/ -run TestLoginIssuesUsableTokenPair -v

# 覆盖率
go test ./... -cover
```

## 测试约定

- fake repository 需随真实接口同步扩展（如新增 `SaveMFASecret` / `EnableMFA` 等方法时，
  测试 fake 必须同步实现，否则编译失败）。
- 2FA 相关测试的 `MFAConfig` 通过 `testMFAConfig()` 统一构造，避免散落魔法值。
- `NewTokenManager` 签名为 `(secret, accessTTL, refreshTTL, mfaTicketTTL)`，测试需传 4 个参数。
- `AuthService.Login` 返回 `(*LoginResult, error)` 两值，断言时注意解构。

## 提交前检查

```bash
go vet ./... && go test ./... && cd ../api-gateway && go vet ./... && go build ./...
```
