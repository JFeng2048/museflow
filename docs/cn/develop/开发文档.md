# 开发文档

## 环境准备

仓库根使用 Go Workspace（`go.work`），无根 `go.mod`。Windows 下无 `make`，
直接在各模块目录执行 `go` 命令。

```bash
# 解析 workspace（新增模块后执行）
go work sync

# 安装工具
go install github.com/swaggo/swag/cmd/swag@latest
go install github.com/air-verse/air@latest   # 热重载（可选）
```

## 本地运行

```bash
# user-service（gRPC :5002）
cd services/user-service && go run ./cmd/server

# api-gateway（HTTP :5001）
cd services/api-gateway && go run ./cmd/server
```

复制 `.env.example` 为 `.env` 填充配置。user-service 的 2FA 配置见
《2FA 双因素认证设计文档》配置项一节。

## 构建与校验

```bash
# 构建
cd services/user-service && go build ./cmd/server
cd services/api-gateway && go build ./cmd/server

# 静态检查
go vet ./...

# 测试
go test ./...

# 单测示例
go test ./internal/service/auth/ -run TestLoginIssuesUsableTokenPair -v
```

## 代码生成

- **gRPC**：`bash scripts/gen-proto.sh`（需 protoc 29.3 + 插件；无 protoc 时回退 `tools/protogen`）。
- **Swagger**：`cd services/api-gateway && swag init -g cmd/server/main.go -o docs --parseDependency --parseInternal`
  （`--parseDependency --parseInternal` 用于解析跨包 DTO 与 `errcode.Response` 泛型响应）。

## 编码约定

- 提交信息：Conventional Commits + 中英双语主题，如 `feat(user-service): 增加 2FA / add 2FA`。
- 配置：统一走 `envloader`，共享键无前缀（`JWT_SECRET`/`REDIS_*`/`DB_*`），服务键加前缀（`USER_`/`GATEWAY_`/`LOG_`）。
- 文案：注释、文档、日志以中文为主；标识符用英文，保持 `gofmt`/`go vet`。
- 分层：handler → service → repository 单向；service 内 `auth`→`token`+`dto` 无环。

## 前端

```bash
cd web && pnpm install && pnpm dev   # 开发

```
